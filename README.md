# s.p.l.i.t 简体中文汉化补丁

给 Steam 正版游戏 **s.p.l.i.t**（Mike Klubnika，Godot 4.4.1）做简体中文汉化的**补丁包**。

> ## ⚠️ 法律声明
> **本仓库不含游戏本体，也不含任何可独立运行的游戏文件。**
> 补丁包（`payload.zip`）里只有 74 个**被改动的资源条目**（编译后的脚本、场景、
> 字体、重绘贴图），必须由你**自备正版游戏**才能使用——应用器会先校验你自己那份
> `split.exe` 的 SHA256，只有**未被修改过的正版原版**才会被打补丁。
> 请通过 Steam 等正规渠道购买游戏。游戏本体及原始资源的版权归原作者所有；
> 本补丁为**非官方**民间汉化，与作者、发行商无关。若权利人提出异议，本仓库会立即下架。

## 一、这是什么

游戏的可执行文件 `split.exe` 里**内嵌**了一个 Godot PCK（`[PE 镜像][PCK 索引][数据区]`）。
本补丁把它改成：

| 项目 | 数量 | 说明 |
|---|---|---|
| 翻译文本 | 458 条 | 英文 → 简体中文 |
| 场景文本槽位 | 37 处真实替换 + 27 处等值槽位 | 6 个 `.scn` |
| 过场字幕 | 67 条 | `forest road.tscn` 打字机累积前缀 |
| 新增中文字体 | 1 个 | `res://fonts/cjk.fontdata`（Noto Sans SC，7,743,989 B） |
| 字体外部引用 | 13 个 `.fontdata` | 各自改为引用上面那一个字体（否则要内嵌约 110 MB） |
| PCK 条目数 | 1346 → 1347 | 新增的字体条目 |
| **对白切分器** | **1 处代码改动** | `scripts/Chat.gd` 兼容全角「：」——译文说话人前缀用全角冒号，原版只按半角 `:` 切分 |
| **UI 贴图重绘** | **13 张 `.ctex`** | 把**烘进图片里的**英文改成中文（内容警告页 / KeskOS 登录框 / hkIRC24 窗框菜单栏与「发送」/ 终端标题栏）。这些不是字符串而是像素，文字型汉化碰不到；用游戏自带中日韩字体重绘，**尺寸不变、等长替换** |

除这 1 处代码改动外，其余重编译脚本与原版逐字符相同（屏蔽字符串/注释内容后比对）。
**保留英文**的：`KeskOS`（系统名）、`DCC`（IRC 专有名词）、`hkIRC24.exe`（文件名）、
`#d9xb1`（频道名）、窗口按钮图形，以及思维打字（`ThoughtManager.gd` 走逐键输入，中文无法这样输入）。

### 校验值

| 文件 | 大小 | SHA256 |
|---|---|---|
| 原版 `split.exe`（你自备） | 407,187,680 B | `2F5E7E3EC06E1E3ECA3623E75DF65DE342DC39E21B886B59BA5D455BC752C9F6` |
| `payload.zip`（本仓库 Release 资产） | 34,099,473 B | `19E8074E2719DF00DEFA2BFCC8654356264C3D1A8DE64DE7B4134D659478BA59` |

### 修订记录（2026-09-29）

初版资产（34,094,559 B / `367DA1AB…`）随附的应用器本身没有缺陷，**但官方成品那一条构建
路径有**，三个问题都在这里修掉了，资产已就地替换（v1.0.0 从未被证明可用，所以没有保留
旧资产）：

1. **索引摘要未刷新（真机实测会卡死）**：13 条重绘贴图当年是「等长原地覆盖」写进去的，
   写的时候没有同步刷新 PCK 索引里的 16 字节 MD5。Godot 在**加载** PCK 时校验这个摘要，
   于是汉化版「点开始」会卡死（Windows 事件 1002）。现在 1347 条索引摘要全部等于
   `md5(条目字节)`，并新增独立验收门 `work/verify_pck_md5.py` 常驻把关。
2. **对白标点缺失**：早前把译文里名字两侧的填充空格删掉时，该加标点的地方直接连成了一
   句话（「…老服务器的请求其他都差不多」）。已按**英文原文**逐条补回 19 处标点/句读
   （逗号、问号、去掉一个多余逗号），语料与 `.gd` 源码同步更新。
3. **字节码写法错误（真机实测会闪退，事件 1000）**：第 2 条最初的落地方式是**绕过编译器、
   直接在 `.gdc` 解压后的常量表里改字符串**（`work/patch_gdc_text.py`）。那种写法违反了
   `core/io/marshalls.cpp` 的 `_encode_string()` 约定——字符串常量后面**必须补齐到 4 字节
   边界**，而它只改了长度前缀、没有重新补齐。于是常量表的后续项整体错位，
   `scripts/Chat_Content.gdc` 的 token 流不再合法，Godot 在
   `GDScriptTokenizerBuffer::set_code_buffer()` 里直接报
   `Index token.type = 116 is out of bounds (Token::TK_MAX = 99)`，游戏启动即崩。
   现在改为**真的重编译**：`gdre_tools.exe --headless --compile=Chat_Content.gd
   --bytecode=4.3.0`，再用 `work/splice_gdc.py` 落进 exe；并且新增常驻验收门
   `work/verify_gdc_bytecode.py`（把 Godot 的
   `GDScriptTokenizerBuffer::set_code_buffer()` 逐行复刻成纯 Python，对成品里 117 个
   `.gdc` 逐个解析，解析不吃满整个缓冲区或出现 `token.type >= 99` 即 FAIL），
   配套负测试 `work/verify_gdc_bytecode_negctl.py` 保证这道门真的会响。

汉化后的 `split.exe` **不是**固定哈希：补丁是在**你自己那份原版**上就地生成的，
产物的哈希与体积取决于本机布局（见下文「自检判据」）。参考成品为
415,216,112 B / `070DD0474EBD80789F0D8818DBDBF6ED50C100673DC23FF448C97E5222755720`。

## 二、怎么用

### 环境要求

- Windows
- **Python 3.8+**（脚本只用标准库，不需要 pip 安装任何东西）

### 步骤

1. 从本仓库的 **Releases** 页面下载 `payload.zip`，和 `apply_patch.py` 放在一起。
2. 找到你自己的正版原版 exe，建议先备份一份：
   ```
   C:\Program Files (x86)\Steam\steamapps\common\s.p.l.i.t\split_Windows\split.exe
   ```
3. 生成汉化版（**不要**直接输出到游戏目录，先输出到别处检查）：

   ```powershell
   python apply_patch.py --exe "C:\Program Files (x86)\Steam\steamapps\common\s.p.l.i.t\split_Windows\split.exe" --payload payload.zip --out split_zh.exe
   ```

4. 退出游戏与 Steam（避免 Steam 在后台校验文件），把 `split_zh.exe` 复制到游戏目录、
   重命名为 `split.exe` 覆盖（**原版请务必留备份**）。

### 参数

| 参数 | 说明 |
|---|---|
| `--exe` | **必填**。你自己的正版原版 `split.exe` |
| `--payload` | 补丁包路径，默认按 `release/payload.zip` → `./payload.zip` 顺序找 |
| `--out` | **必填**。输出路径（不能与 `--exe` 相同，防止毁掉你唯一的回滚源） |
| `--ref` | 可选。官方成品 exe，用于做「逐条相同」自检（自己有才需要） |
| `--report` | 可选。把完整报告另存为文本文件 |
| `--no-ref-check` | 跳过与 `--ref` 的逐条比对 |

脚本做四件事：

1. 算输入 exe 的 SHA256，**不等于补丁包要求的原版哈希就拒绝并说明原因**
   （防止把补丁打到别人已经改过的文件上）；
2. 从 `payload.zip` 读出 74 个条目，**逐条核对长度与 SHA256**（补丁包损坏会当场发现）；
3. 打进 PCK：72 个条目就地替换，1 个新条目（字体）追加进目录 —— 目录变长后
   数据区整体后移 64 字节，再回填 **PCK 索引 / PCK 头 file_base / 尾部 ds /
   PE `pck` 段 SizeOfRawData**（过程与 `work/splice_gdc.py`、`work/inject_slots.py` 一致）；
4. 重新解包产物，**逐条回读比对**，任何一条对不上就报 FAIL。

### 回滚

把备份的原版 `split.exe` 复制回去即可；没有备份就在 Steam 里
**右键游戏 → 属性 → 已安装文件 → 验证游戏文件完整性**，Steam 会重新下载原版。

## 三、自检：判据是「条目级逐条相同」，不是「整文件逐字节相同」

`apply_patch.py` 自带端到端自证（`--ref` 指向官方成品时）：

- **自检判据**：解包后条目名集合相同，且 **1347 个同名条目的字节逐条逐字节相同**。
- **为什么不用「整文件逐字节相同」**：官方成品当初是先用 GDRE `--pck-patch/--embed`
  **全量重建**过 PCK（条目按 16 字节重排，条目间间隙从 9,734 B 变成 21,358 B），
  再叠加两次二进制 splice 得到的；而本应用器是从零售 exe 出发做**最小改动**，
  数据区布局必然不同 —— 整文件逐字节相同在物理上不成立。条目本身是自包含的
  （RSRC / 编译字节码 / 贴图 / 字体，内部偏移都是相对 blob 的），布局差异不影响语义。

本机实测结果见 [`e2e-report.txt`](e2e-report.txt)：以原版 exe 为输入，
产物 **条目 1347 / 相同 1347 / 不同 0**，且与官方成品 `dist/split.exe`
「共同条目 1347 个，逐条相同 1347，不同 0」，VERDICT: PASS。
产物体积 415,204,482 B（官方成品 415,216,112 B，差 11,630 B 全部来自数据区间隙布局）。

## 四、实机确认状态 ⚠️

构建阶段的自动化验证（PCK 结构、逐槽位字节回读、字形覆盖率、PE 完整性、索引摘要自洽）
**全部通过**。

**已由用户真机确认**：汉化版能正常启动（主菜单 → 点开始 → 进入游戏），并且聊天里显示的是
汉字而不是方框/问号/空白 —— 附带说明了「字形是否存在」与「能否进游戏」这两层已不是风险
（此前卡死的根因是 13 条 PCK 索引摘要没刷新，不是字形也不是贴图编码，已修复并加了常驻门）。

**仍需目视确认**（与 2026-09-29 的重建无关，属既有外观项）：

1. **中文在定宽终端里的列位**：终端是等宽字体，列位完全由原文里的字面空格决定。
   实测出货字体宽 **1 汉字 = 3200/1300 = 2.4615 格**，旧语料按「1 汉字 = 2 格」补空格，
   于是宽表（囚犯名册 / 机架图 / `system_config` 列表 / 设备扫描表 / KeskOS 启动日志）
   逐行参差，最差 8.77 格。**2026-09-30 已按真实比例重排**（只改空格，不动译文文字）：
   `work/verify_colwidth.py` 逐锚点钉死，**1115 个列锚点中 1114 个落在英文格线上
   （< 0.5 格），0 行溢出**。唯一例外是 `blk/01` 第 29 行（英文字段 12 格、
   译名「克里斯蒂亚」= 12.31 格，算术上不可对齐），已按精确值（8/13 格）登记。
2. **打字机逐字动画**在中文下的表现（有无半字/断字）。
3. 2026-09-29 新增的 19 处标点/句读修正**尚未在真机上重新走一遍**。不过在机器可判的层面
   这一版已经是干净的了：`Chat_Content.gd`（8875 B）→ GDRE 编译 → 落进 exe 的 `.gdc` →
   GDRE 反编译，**往返得到的 `.gd` 与源文件逐字节相同**；成品里 117 个 `.gdc` 也全部通过
   `work/verify_gdc_bytecode.py` 的字节码解析。如果你在对话里看到标点有误，请把截图发来。
